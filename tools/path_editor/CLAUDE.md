# Trailforge — AI Coder Reference

Internal orientation document. Read this before touching anything.

---

## What This Tool Is

A four-pane 3D spline path editor (Trailforge) for Super Spaceguy Shooter. Designed
paths are saved to `../../assets/maneuvers.txt` and read by the QB64-PE
game at runtime. The editor runs as a Vite/React SPA; the dev server also
exposes a `/api/maneuvers` endpoint that reads/writes the file directly.

**Run:** `npm run dev` → http://localhost:5173  
**Build:** `npm run build` → `dist/`  
**No tests.** Build clean = done.

## Store (`src/store.ts`)

**Single source of truth.** Use `useStore()` in components; use
`useStore.getState()` inside event handlers and callbacks.

### State fields

| Field | Type | Purpose |
|-------|------|---------|
| `path` | `PathData` | The active route (name, speed, orient, target, standoff, closed, wps[]) |
| `selected` | `number` | Active waypoint index; -1 = none. Drives sidebar roll panel. |
| `multiSel` | `number[]` | Marquee multi-selection indices. Empty = single-select mode. |
| `playing` | `boolean` | Animation running |
| `animT` | `number` | Current animation parameter (0..wps.length, arc-length correct) |
| `frameR` | `Vec3` | Right vector from parallel-transport frame at current animT |
| `frameU` | `Vec3` | Up vector from parallel-transport frame at current animT |
| `status` | `string` | Status bar message |
| `debugLog` | `boolean` | Log per-frame vectors to console |
| `showOverlays` | `boolean` | Show game-context overlays (range planes, scale reference) |
| `maximizedPane` | `PaneName \| null` | Which pane fills the viewport; null = 4-pane |
| `editGhost` | `{path,wpIdx}\|null` | Triggers NodeEditDialog; snapshot of path at dialog-open time |

### Actions

| Action | Effect |
|--------|--------|
| `setPath(p)` | Replace entire path; normalizes (deduplicates closed loop endpoint); saves to localStorage |
| `patchPath(key, value)` | Update one PathData field; renormalizes if key==='closed' |
| `setWp(i, wp)` | Replace one waypoint; saves to localStorage |
| `replaceWps(wps[])` | Replace all waypoints at once (used by shape generator, bulk ops) |
| `addWp(vec3, after?)` | Insert waypoint after index (or append); sets `selected` to new index |
| `delWp(i)` | Delete waypoint; clears `selected` |
| `dupWp(i)` | Duplicate waypoint; sets `selected` to i+1 |
| `setSelected(i)` | Set active waypoint |
| `setMultiSel(indices[])` | Set marquee multi-selection |
| `setPlaying(v)` | Start/stop animation |
| `setAnimT(v)` | Set animation position directly |
| `setPlayState(animT,frameR,frameU)` | Called 60×/s by animation loop — does NOT go into undo history |
| `setStatus(s)` | Update status bar |
| `setMaximizedPane(pane\|null)` | Maximize a pane or restore 4-pane |
| `setEditGhost(g\|null)` | Open/close NodeEditDialog |

### PathData shape

```ts
interface PathData {
  name:     string       // route key in maneuvers.txt
  speed:    number       // world-units/frame, arc-length corrected
  orient:   'path' | 'target'
  target:   Vec3         // used when orient==='target'
  standoff: number       // perpendicular offset from wire curve
  closed:   boolean      // loop back to first waypoint
  wps:      Waypoint[]   // [{x,y,z,pathRoll,craftRoll}, ...]
}
```

### Undo system (zundo)

- `temporal` middleware wraps the store; `limit: 100` entries
- **Only `path` is tracked** (`partialize`); all UI state (selected, playing, etc.) is excluded
- **Reference equality guard**: `equality: (a,b) => a.path === b.path` prevents the 60Hz `setPlayState` from flooding the history ring
- **Undo/redo**: `useStore.temporal.getState().undo()` / `.redo()`
- **For drag operations**: ALWAYS use `pauseAfterCheckpoint()` at drag start, `resumeTemporal()` at drag end. This pushes ONE clean entry (the pre-drag state) and ignores all the intermediate setWp calls.
- `pauseAfterCheckpoint()` uses `_handleSet` (internal zundo API, cast through `unknown`) to manually push a snapshot before pausing

## Undo Helpers (`src/views/undoHelpers.ts`)

```ts
pauseAfterCheckpoint()  // call at START of any drag or multi-step op
resumeTemporal()        // call at END (mouseUp, dialog close)
```

**Rule**: Every drag (wp drag, mwp drag, rotate, translate) must bracket with these. NodeEditDialog does the same. Failure to call resume leaves undo paused and nothing records after that.

## Ortho Views — Shared Pattern

All three views (`TopView`, `SideView`, `FrontView`) are structurally
identical templates. Differences are only which world axes they control
and which rotation function they import.

### Axis mappings

| View | Screen-X → | Screen-Y → | Rotation axis | `w2s` args |
|------|-----------|-----------|---------------|-----------|
| TOP (XZ) | world Z | world X (inv) | rotateAroundY | `(wx, wz)` |
| SIDE (XY) | world X | world Y (inv) | rotateAroundZ | `(wx, wy)` |
| FRONT (YZ) | world Z | world Y (inv) | rotateAroundX | `(wz, wy)` |

"Inverted" means screen-Y increases downward but world-Y increases upward.

### DragState union (per view)

```ts
type DragState =
  | { type: 'wp';        wpIdx, startSx, startSy, startW{A}, startW{B} }
  | { type: 'mwp';       startSx, startSy, starts: [{idx, w{A}, w{B}}] }
  | { type: 'marquee' }   // screen coords live in marqueeRef, not here
  | { type: 'pan';       startSx, startSy, startPan, startScale }
  | { type: 'rotate';    startSx, snapshotWps }
  | { type: 'translate'; startSx, startSy, snapshotWps }
```

Where `{A}` and `{B}` are the two world axes that view controls.

### Gesture routing (onMouseDown)

```
Alt + left drag          → rotate (whole path)
Ctrl + left drag         → translate (whole path)
Middle button drag       → pan camera
Right button drag        → pan camera + record ctx menu hit
Left on node in multiSel → mwp (multi-drag all selected nodes)
Left on node             → wp drag (clears multiSel)
Shift + left on empty    → marquee selection
Left on empty            → pan (clears multiSel)
```

### Marquee selection

- `marqueeRef` (a `useRef`) stores `{startSx,startSy,curSx,curSy}` — drawn directly in `draw()` without React state to avoid re-renders
- `onMouseMove`: updates `marqueeRef.current` coords, calls `drawRef.current()` manually
- `onMouseUp`: hit-tests all wp screen positions against rect, calls `setMultiSel(found)`, clears ref

### Multi-node drag (mwp)

- Stores starting world coords of all selected nodes in `starts[]`
- `onMouseMove`: applies same screen delta to all nodes relative to their individual start positions
- `onMouseUp`: `resumeTemporal()` — one clean undo entry for the whole group move

### Draw pattern

```ts
const draw = useCallback((ctx, w, h) => {
  // 1. clear + grid
  // 2. game-context overlays (if showOverlays)
  // 3. ghostRef (drag ghost — shows pre-drag spline)
  // 4. editGhost (NodeEditDialog ghost — shows pre-edit spline)
  // 5. live spline + standoff line
  // 6. origin crosshair
  // 7. target crosshair (if orient==='target')
  // 8. waypoint dots (grey=normal, yellow=selected, purple=multiSel)
  // 9. ship model (if playing, uses makeFrame when orient==='target')
  // 10. axis labels
  // 11. rotate/translate hint
  // 12. marquee rect (reads marqueeRef directly)
}, [path, selected, multiSel, playing, animT, frameR, frameU, showOverlays, editGhost])

const { cvRef, draw: redraw } = useOrthoCanvas(draw, [/* same deps */])
```

`drawRef = useRef(redraw); drawRef.current = redraw` — stable ref to force redraws imperatively during drags without React state changes.

### Ship orientation in ortho views

**Critical**: when `orient === 'target'`, use `makeFrame(facing)` for R/U — NOT `frameR`/`frameU`.  
`frameR`/`frameU` are the parallel-transport frame (orthogonal to the *path tangent*).  
`makeFrame(facing)` builds a Gram-Schmidt frame orthogonal to the *target-facing direction*.  
Using the wrong frame causes a garbage quaternion and wrong ship orientation.

```ts
const { R, U } = path.orient === 'target'
  ? makeFrame(facing)
  : { R: frameR, U: frameU }
```

This applies in ALL four views (TopView, SideView, FrontView, PerspView).

## Camera System (`src/views/orthoCamera.ts`)

All three ortho views share camera state through a module-level singleton (not React state, not the store). This allows linked pan/zoom.

```ts
getCam(view: 'top'|'side'|'front') → { scale, worldPan: {x,y,z} }
notifyAll()   // trigger redraws in all ortho views after camera change
```

`useOrthoCanvas` subscribes to camera notifications and redraws when they arrive.

**Linked mode**: when `orthoLinked` is true (toggled with `L`), pan/zoom changes in one view sync to all others via `notifyAll()`.

## Math Layer

### `src/math/spline.ts` — THE CORE

| Export | Purpose |
|--------|---------|
| `buildSpline({wps,closed,standoff})` | Returns `SamplePoint[]` at uniform arc-length intervals. Each sample has `{wire,actual,t}`. `wire` is on the Catmull-Rom curve; `actual` is offset by standoff + pathRoll. |
| `evalAt(wps,t,closed)` | Evaluate wire position at parameter t (0..n) |
| `tangentAt(wps,t,closed)` | Tangent vector at t |
| `actualPos(wire,tan,pathRollDeg,standoff)` | Compute standoff-offset position |
| `evalRollAt(wps,t,closed,'pathRoll'|'craftRoll')` | Interpolated roll at t |
| `shipFacing(wirePos,tangent,orient,target)` | Returns normalized facing direction. `path` mode: normalized tangent. `target` mode: normalized vector from wirePos to target. |
| `makeFrame(facing)` | Gram-Schmidt orthonormal frame `{R,U}` from a direction vector. Use when orient==='target'. |
| `frustumAtX(x)` | Game camera frustum geometry at world-X position |

### `src/math/spline_gen.ts` — AUTO-GENERATED

**DO NOT EDIT.** Generated by `node tools/emit-spline.js` from `../../math/formula.expr` (ExprForge DSL). The Vite dev server watches the `.expr` file and re-emits automatically. If you need to change the parallel-transport frame math, edit the `.expr` file, not the generated TypeScript.

### `src/math/pathOps.ts`

```ts
rotateAroundX(wps, theta)    // rotate all wps around world X axis at centroid
rotateAroundY(wps, theta)    // around Y (used by TopView Alt+drag)
rotateAroundZ(wps, theta)    // around Z (used by SideView Alt+drag)
translateWps(wps, dx, dy, dz)
```

### `src/math/vec3.ts`

`Vec3 = {x,y,z}`. Helpers: `v3.add`, `v3.sub`, `v3.scale`, `v3.dot`, `v3.cross`, `v3.norm`, `v3.len`.

## PerspView (`src/views/PerspView.tsx`)

Three.js scene. Does NOT use `useOrthoCanvas` or the camera singleton.

- **Camera modes**: `orbit` (trackball), `follow` (trails ship, scroll = distance), `in-game` (fixed at game camera position looking along +X)
- Waypoints are clickable spheres → calls `setSelected(i)`
- Ship model is a Three.js mesh group updated each animation frame
- **Focus**: wrapper div has `tabIndex={0}` + `onMouseEnter` → `.focus()` so keyboard events (F key) reach `onRootKeyDown` in App.tsx

**Does not implement drag, marquee, or undo** — all editing is done in ortho views.

## Pane Maximize

Handled entirely in `App.tsx`. Do not re-implement in views.

```ts
const toggleMax = (pane: PaneName) =>
  setMaximizedPane(maximizedPane === pane ? null : pane)
```

- **Corner wedge click** → `toggleMax(pane)`
- **F key** → `toggleMax(hoveredPane.current)` — `hoveredPane` is a `useRef<PaneName|null>` updated by `onMouseEnter`/`onMouseLeave` on each view-cell div
- **Esc** → `setMaximizedPane(null)` (in `onRootKeyDown`)
- Each view-cell div has `onMouseEnter` → `hoveredPane.current = pane` and `onMouseLeave` → `null`

## Keyboard Routing

Two handlers in `App.tsx`, plus per-view `onKeyDown`:

| Handler | Where | What |
|---------|-------|------|
| `window.addEventListener('keydown')` | `useEffect` in App | Ctrl+Z/Ctrl+Shift+Z (undo/redo) — fires regardless of focus |
| `onRootKeyDown` | `.app` div `onKeyDown` | L (linked), Esc (restore), F (maximize hovered pane) — skips inputs |
| `onKeyDown` in each ortho canvas | React `onKeyDown` | Del/Backspace (delete selected wp) |

**Focus stealing**: Each ortho canvas and PerspView wrapper has `onMouseEnter={() => element.focus()}`. This ensures keyboard events reach `onRootKeyDown` without requiring a click first.

## UI Components

### `ContextMenu` (`src/ui/ContextMenu.tsx`)

Props: `{x, y, wpIdx, onClose, onAddHere?, onEditCoords?}`

- `wpIdx >= 0`: waypoint menu (Edit Coords / Delete / Duplicate / Insert After)
- `wpIdx < 0`: empty-space menu (Add Waypoint Here)
- Closes on outside click (deferred one tick) or Escape
- `onEditCoords` triggers NodeEditDialog: caller must call `pauseAfterCheckpoint()` then `setEditGhost({...})` before closing ctx menu

### `NodeEditDialog` (`src/ui/NodeEditDialog.tsx`)

Always mounted in `App.tsx`. Self-shows/hides based on `editGhost` store field.

- Local string state for X/Y/Z prevents mid-keystroke clobbering
- Live preview: each valid input change calls `setWp` immediately
- Temporal is paused while open (paused by the `onEditCoords` caller before `setEditGhost`)
- **Set**: calls `resumeTemporal()` then `setEditGhost(null)` → one clean undo entry
- **Cancel**: restores original coords from `editGhost.path.wps[wpIdx]`, then `resumeTemporal()`, then `setEditGhost(null)` → no undo entry

### `GenerateDialog` (`src/ui/GenerateDialog.tsx`)

Shapes: `blank | circle | ellipse | figure8 | helix | arc`

- **`newRoute` prop**: creates a fresh route (`name='untitled'`, `speed=0.25`) instead of replacing waypoints in place
- Settings persisted to `localStorage` key `'trailforge:gen-settings'`; loaded on next open
- **Blank shape**: single waypoint at `(10,0,0)`, no params shown

## IO Layer

### `format.ts`

```ts
exportBlock(path: PathData): string    // → one [route_name]\n... block
parseBlocks(text: string): Map<string, PathData>   // ← full maneuvers.txt
```

### `RoutesPanel.tsx`

- Fetches `/api/maneuvers` on mount (GET); PUT to save
- `isDirty` = `savedPath !== null && JSON.stringify({...path,name:savedPath.name}) !== JSON.stringify(savedPath)`
- **Load**: dirty guard → `setPath(block)` + `setSavedPath(block)`
- **Save**: writes under `path.name`; updates both `allBlocks` and `setSavedPath`

- **+ New**: dirty guard → shows `GenerateDialog` with `newRoute` prop
- API only available in dev server; falls back gracefully in production

### `/api/maneuvers` (Vite plugin in `vite.config.ts`)

GET → reads `../../assets/maneuvers.txt`  
PUT → writes `../../assets/maneuvers.txt`

## Session Persistence

`path` is saved to `localStorage('trailforge:session')` on every `setPath`/`patchPath`/`setWp`/etc. call, and also on every undo/redo (via a `useStore.subscribe` listener). Restored on page load.

## ExprForge / Spline DSL Constraint

**The parallel-transport frame math in `spline_gen.ts` is shared with the QB64-PE game.** Any change to that math MUST go through the ExprForge DSL at `../../math/formula.expr`. Never duplicate or override this math by hand in TypeScript or QB64. The Vite watcher re-generates `spline_gen.ts` automatically when the `.expr` file changes.

## Behaviors Panel — Invariants

These rules apply to ALL behavior tracks, including `craftRoll`. Violating any is a regression.

### Track visibility lifecycle
- A track row is **only visible when it has data** (keyframes or segments > 0).
- When the last item is removed, the row disappears immediately. Auto-collapse expansion state.
- Tracks are added via **+ Add** menu. Removing all items ≠ deleting the track concept — the user can always re-add it via + Add.

### CraftRoll vs keyframe tracks
`craftRoll` is **segment-based** (`path.craftRollSegments: CraftRollSegment[]`), not a keyframe track in `path.tracks`. It uses a completely separate store slice and UI component (`CraftRollTrack`). Do NOT look for craftRoll in `path.tracks` — it will never be there.

**All four views** (TopView, SideView, FrontView, PerspView) read craftRoll from `path.craftRollSegments` via `evalCraftRoll(segments, arcFrac)`. If you change where craftRoll data lives, update ALL four views. Grep for `evalCraftRoll` to find all callsites.

### CraftRollTrack interaction contract
| Action | How |
|--------|-----|
| Add segment | Right-click empty ruler → "Add roll segment here", OR press **N** when track is expanded (adds at playhead) |
| Select segment | Click segment block body |
| Move segment | Drag segment body |
| Resize segment | Drag left/right edge handles |
| Delete segment | Right-click segment body → "Delete segment", OR select + Del button in expanded editor |
| Remove ALL segments | Click **×** button in track right panel (with confirm dialog) |
| Clear entire track | Same as "Remove ALL" — after last segment gone, row vanishes |
| Re-add after clear | **+ Add → craftRoll** |
| Mute | Eye button (◉/○) in right panel |

**Never** add a click-to-add handler on the ruler. Accidental clicks on the timeline create unwanted segments.

### CraftRoll segment fields
```ts
interface CraftRollSegment {
  id:        string
  t:         number           // arc-length fraction [0, 1] — NOT parameter fraction
  duration:  number           // arc-length extent, min 0.01
  degrees:   number           // 0–360 for absolute; 1–3600 for relative
  direction: 'cw' | 'ccw'
  mode:      'relative' | 'absolute'
  ease:      'linear' | 'in' | 'out' | 'in-out'
}
```

`t` is stored in arc-length space (same coordinate system as the CraftRollTrack ruler). Do NOT apply `paramToArc` to it — unlike keyframe tracks where `kf.t` is parameter fraction, `seg.t` is already arc fraction.

### Roll arc visualization
All views draw a roll clock indicator (ring + radial arm) at each waypoint when `path.craftRollSegments.length > 0`. Orange = CW (positive degrees), Blue = CCW (negative). The arm points in the direction of the accumulated roll angle using a clock-face convention (12 o'clock = 0°, clockwise positive).

PerspView adds a 3D ring (torus, perpendicular to ship forward axis) + white arm to the ship group in `buildShipGroup()`. Because the whole group rotates with the ship, these always reflect actual bank angle.

## Common Mistakes to Avoid

1. **Orient toggle — wrong frame vectors**: Use `makeFrame(facing)` when `orient==='target'`. Never pass `frameR`/`frameU` in target mode. Applies in all 4 views.

2. **Undo flooding**: `setPlayState` fires 60×/s. The `equality` guard in zundo prevents this from filling the history ring. Don't remove it. Don't add other high-frequency `set()` calls to fields that ARE tracked by `partialize`.

3. **Drag without pause/resume**: Any drag that calls `setWp` repeatedly needs `pauseAfterCheckpoint()` at start and `resumeTemporal()` at end, or every mouse-move frame becomes an undo entry.

4. **Editing `spline_gen.ts`**: Don't. It gets overwritten by the emitter.

5. **Adding state outside the store**: Don't. The store is the single source of truth. Local component state is only for UI-only concerns (dialog open/close, input strings, drag refs).

6. **`multiSel` vs `selected`**: `selected` is the "primary" node for the sidebar roll panel. `multiSel` is the marquee set. Both can be set simultaneously (first marquee node is also `selected`). Clearing `multiSel` via `setMultiSel([])` does NOT clear `selected`.

7. **Drawing the marquee**: `marqueeRef` (a plain `useRef`) stores coords; the draw callback reads it directly. No React state, no re-render — just call `drawRef.current()` imperatively in `onMouseMove`.

8. **PerspView keyboard**: PerspView wrapper div has `tabIndex={0}` + `onMouseEnter→focus()`. Without this, F key doesn't work in full-frame persp mode because nothing is focused to bubble events to `onRootKeyDown`.

9. **Save As updates store name**: `doSave(newName)` calls `setPath(updated)` so the toolbar Name field reflects the saved name. Don't forget this if you ever refactor the save path.

10. **CraftRoll consumers — ALL four views**: When changing anything about craftRoll evaluation (data shape, evaluator function, store field name), update TopView, SideView, FrontView, and PerspView. Grep `evalCraftRoll`. Missing even one is a silent regression in that view's playback.
