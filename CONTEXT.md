# Super Spaceguy Shooter — Codebase Context

> Read this before exploring any system. It is the shared vocabulary and map for this codebase.
> It reflects the `origin/master` state; pull before a new session if significant time has passed.

## What this is

A cinematic rail-shooter written entirely in QB64-PE (QBasic). No game framework, no graphics library, no audio library, no GPU. Every pixel is software-rasterized by the CPU. Every sound is synthesized mathematically. Every asset is baked into the binary at compile time via `$EMBED`. The output is a single self-contained native binary (Linux/macOS/Windows). Network telemetry and leaderboards are optional and off unless `assets/.env` is configured.

## Source layout

```
3d/                         ← git root; this is where git commands target
├── sss.bas                 ← entry point; $EMBEDs assets, $INCLUDEs manifests, main loop
├── src/
│   ├── game.bi             ← include manifest for all non-3D modules (in dep order)
│   ├── engine3d.bi         ← include manifest for the 3D engine
│   ├── sys/                ← core systems: game state, CLI, sequencer, settings, HTTP, telemetry, JSON, leaderboard, debug
│   ├── 3d/                 ← software 3D pipeline: mesh, matrix, poly, camera, collision, starfield
│   ├── audio/              ← music.bas, snd.bas (mixer/SFX), speech.bas (TTS)
│   ├── gameplay/           ← player, enemy, boss, waves, behavior, stage/level logic, maneuvers
│   ├── state/              ← per-screen game states: title, crawl, combat, asteroids, game over, consent, username, leaderboard, lead-in, dock, remap, pause input
│   └── 2d/                 ← HUD, UI panels, bitmap font, particle effects, crawl renderer, about and controls screens, text editing
├── assets/                 ← all game assets (embedded at compile time -- no runtime file I/O)
│   ├── models.e3d          ← custom text mesh format (all 3D geometry)
│   ├── sequence.txt        ← data-driven scene list
│   ├── gametext.txt        ← all spoken/displayed text (source of truth for speech dict)
│   ├── config/             ← tuning data: economy.ini (credits), upgrades.ini (dock table), abilities.ini (nova / roll)
│   ├── speech_dict.txt     ← baked phoneme dict (regenerated by tools/bake_speech_dict)
│   └── .env                ← gitignored; DB_URL + DB_KEY for the telemetry backend (absent = no network)
├── server/                 ← telemetry/leaderboard backend: Cloudflare Worker + D1 (TypeScript, Vitest)
├── tests/                  ← self-contained .bas test programs (exit 0 = pass)
└── tools/                  ← buildqb, bake_speech_dict, TrailForge (web tool), obj2e3d, viewer, etc.
```

`sss.bas` is the only file QB64-PE compiles directly. It `$INCLUDE`s `src/sys/version.bas`, `src/sys/rng.bas`, `src/engine3d.bi`, `src/sys/dims.bas` and `src/game.bi` in that order (the two manifests pull in every other module), and then, inline after the startup code, the seven main-loop states `src/state/title.bas`, `intro.bas`, `gameover.bas`, `crawl.bas`, `playing.bas`, `asteroids.bas` and `combat.bas`. New modules go in `src/game.bi`, not as another `$INCLUDE` in `sss.bas`.

## Domain vocabulary

| Term | Meaning |
|---|---|
| **stage** | One of six numbered combat/boss/asteroid levels. A sequence of `PLAY` waypoints in `sequence.txt`. |
| **waypoint** *(sequencer)* | A named entry in the linear `SEQ_` table (CRAWL, CARD, TITLE, PLAY, ARRIVE, DOCK). Completely unrelated to path-editor waypoints. |
| **cue** | A named music segment (`"intro"`, `"game"`, `"boss"`, `"outro"`). Triggered by name; engine crossfades or cuts. |
| **wave** *(audio)* | A synthesized sample buffer in `snd.bas`/`wave.bas`. |
| **wave** *(enemies)* | A timed spawn group of enemies scheduled in `stage.bas`. Context disambiguates; they never appear in the same file. |
| **obj / object** | A live game entity: position, velocity, optional mesh reference, behavior pointer. Not the same as a mesh. |
| **mesh** | Loaded `.e3d` geometry: vertex array + face array. One mesh definition, many object instances. |
| **behavior** | An AI update function (`BEH_*`) attached to an enemy object; called each frame. |
| **phoneme** | An ARPAbet speech sound unit. `SPK_Say` converts text → phoneme queue → waveform samples. |
| **coarticulation** | Crossfade between adjacent voiced phoneme wavetables, preventing click artifacts. |
| **pattern** | A sequence of notes in `music.bas`. Arranged into named cues. |
| **sequence** / **sequencer** | `src/sys/sequence.bas` — drives the full game flow. NOT the music engine. |
| **offscreen buffer** | A QB64 `_NEWIMAGE` page used for double-buffering; rendered to, then flipped with `_Display`. |
| **e3d** | The custom text-based mesh format used by the game. `assets/models.e3d` holds all geometry. |
| **crawl** | The Star-Wars-style scrolling narrative text. Rendered by `src/2d/crawl.bas`. |
| **telemBatch** | In-memory buffer of JSON event objects, POSTed as one array at session end. |

## Coordinate system (3D engine)

```
X = forward   (into screen / camera look direction)
Y = up
Z = left
```

Camera trails behind (-X) and above (+Y) the player. All `.e3d` mesh data uses this convention. `obj2e3d.bas` supports `remap` arguments for models authored in Blender's +Z-up convention.

## Architectural invariants — never violate these

1. **No runtime file I/O.** Assets are baked via `$EMBED`. The only files a player's game touches are `sss_settings.ini` (written/read by `settings.bas` for persistence) and `sss_telemetry.csv` (written by `telemetry.bas` for local logging), both in the launch folder. Dev builds also read `--input-script` / `--leaderboard-file` files and write `--screenshot-at` PNGs and the `SSS_MILESTONE_LOG` file.
2. **Single compiled binary.** No DLLs, no plugins, no dynamic loading.
3. **Single thread.** The frame loop is: input → update → render → `_Display`. `HTTP_Pump` must be called once per frame from the main loop for async transfers to make progress.
4. **All state is module-global.** `src/sys/dims.bas` declares the game-wide state; most modules also declare their own `DIM SHARED` variables at the top of the file (about 60% of all `Dim Shared` lines live outside `dims.bas`). Either way every shared variable is global: no module has private state that another module cannot read.
5. **Name prefix = module owner.** `SEQ_Advance` belongs to `sequence.bas`. Don't add sequence logic to `stage.bas`.
6. **$INCLUDE order is deps order.** `src/game.bi` and `src/engine3d.bi` pull in modules in the correct order. New modules belong there, not as direct `$INCLUDE` in `sss.bas`.
7. **All spoken text must live in `gametext.txt`.** Never pass a string literal to `SPK_Say`. `bake_speech_dict` must be able to see every word that will be spoken or the CI dict-check will fail.
8. **Speech dict must be rebaked on gametext changes.** After editing `assets/gametext.txt` or `assets/gamevalues.ini`, run `bash tools/bake_speech_dict` and commit `assets/speech_dict.txt`. CI will fail otherwise.
9. **`E3D_SceneBegin`/`E3D_SceneFlush` must be paired per frame.** Unpaired calls draw a stale or partial batch with no assertion.
10. **`HTTP_Flush` blocks.** Call it only at shutdown paths, never from the main game loop.

## Things that do NOT exist (don't hallucinate them)

- No GPU — the 3D renderer is 100% CPU (software rasterizer in `src/3d/poly.bas`)
- No audio files — all sound is synthesized in `snd.bas` / `music.bas` / `speech.bas`
- No Makefile, no CMake, no `npm` — build is `./tools/buildqb sss.bas`
- No general JSON decoder — `json.bas` encodes only; all response parsing is hand-rolled per consumer
- No texture mapping — faces are flat-colored with optional directional lighting
- No unit test framework — tests are self-contained `.bas` programs in `tests/` that exit 0 on pass
- No class system — QB64-PE has `TYPE` structs but no methods or inheritance
- Almost no dynamic allocation — array sizes are fixed at compile time (the one `ReDim` is in `E3D_CtrlScan`, `src/3d/input.bas`). A non-`Static` array `Dim`med inside a Sub is allocated on every call, though, so hot-path workspaces are `Dim Shared`
- **`E3D_DrawMesh` and `E3D_GetMeshFaces` are dead code** — they have no callers in the game, tools, or tests. Do not assume they're in use without checking call sites.

## QB64-PE language notes

These cause incorrect code in this codebase:

- **`DIM SHARED` must appear before `$INCLUDE` lines** in the including file, or included Subs see 0. `src/sys/dims.bas` is the canonical place for game-wide vars; state only one module uses goes at the top of that module.
- **`NOT` is bitwise**, not logical: `NOT 1 = -2` (truthy). Use `IF flag = 0` to guard disabled features. Booleans must be `0` / `-1`.
- **Short names collide with QB64-PE built-ins**: `pos`, `val`, `len`, `tab`, `point`. Prefix with context (`objPos`, `sndVal`).
- **A plain `DIM` outside any Sub is module-level and invisible to Subs** (use `DIM SHARED`). A `DIM` inside a Sub is local to that Sub: the same local name in two Subs is fine (dozens already are, some with different types). Don't give a Sub-local the name of a `DIM SHARED` variable.
- **`UBOUND` on an empty array** returns -1, not 0. Guard with `IF UBOUND(arr) >= 0` before iterating.
- **`STR$(n)` prepends a space** for positive numbers. Use `LTRIM$(STR$(n))` when concatenating.
- **`CONST` scope**: constants declared inside a Sub are local to it. Module-level constants go at the top of the file before any Sub.
- **`_COMMAND$(n)` subscript form** is not supported in QB64-PE v4.5.0. Use `COMMAND$` (full string) and parse it manually.
- **Test stubs replicate shared vars.** Adding a new `$INCLUDE` to `sequence.bas`, `dims.bas`, or any file test stubs replicate means updating every affected test file. Grep for the variable name in `tests/` to find which stubs need it.

## Build and test quick reference

```bash
# Full build (from repo root 3d/)
tools/buildqb sss.bas

# Smoke test
builds/sss --version                      # must print version and exit 0

# Jump straight to a named scene (fastest manual test)
builds/sss --scene boss3                  # stage 3 boss fight
builds/sss --scene playing2               # stage 2 combat

# Full test suite (same as CI)
tools/test                                # native, uses the qb64pe on PATH
tools/dev test                            # in the container

# Individual tests
tools/buildqb tests/seq_trace_test.bas         && builds/seq_trace_test
tools/buildqb tests/seq_dispatch_test.bas      && builds/seq_dispatch_test
tools/buildqb tests/scene_jump_planet_test.bas && builds/scene_jump_planet_test
tools/buildqb tests/telem_creds_test.bas       && builds/telem_creds_test
tools/buildqb tests/snd_init_test.bas          && builds/snd_init_test
tools/buildqb tests/dbg_output_test.bas        && builds/dbg_output_test
tools/http_queue_test                          # needs Python; starts mock server automatically

# Golden-screenshot render tests (tests/render/; --update re-blesses goldens)
tools/dev render

# Rebake speech dict (required after gametext changes)
bash tools/bake_speech_dict

# Preview a 3D mesh without booting the game
tools/buildqb viewer.bas && builds/viewer
```

## Where to look for X

| Question | Answer |
|---|---|
| Where does game flow live? | `src/sys/sequence.bas` — `SEQ_Load` parses `sequence.txt`, `SEQ_Advance` steps forward |
| Where does combat live? | `src/gameplay/stage.bas` (wave scheduling) + `src/gameplay/behavior.bas` (per-enemy AI) |
| Where do boss fights live? | `src/gameplay/boss.bas` (phases) + `BOSS_UpdateMovement` in `src/gameplay/behavior.bas` (hunt/evade movement). The spline flyover states are unused; see `docs/adr/0001-rail-shooter-scope.md` |
| Where does audio happen? | `src/audio/snd.bas` (SFX triggers) + `src/audio/music.bas` (music engine) |
| Where does speech happen? | `src/audio/speech.bas` — call `SPK_Say text$` (text$ must come from `gametext.txt`) |
| Where do shared globals live? | `src/sys/dims.bas` — the game's shared memory layout |
| Where do types/constants live? | `src/3d/types.bi` (3D types), `src/sys/dims.bas` (game types and game-wide constants), and the top of each module for its own constants. `src/game.bi` holds only `$INCLUDE` lines |
| Where does 3D rendering happen? | `src/3d/matrix.bas` → `src/3d/scene.bas` (batching) → `src/3d/poly.bas` (rasterization) |
| Where do meshes come from? | `assets/models.e3d` (embedded); `tools/buildqb viewer.bas` to preview; `obj2e3d.bas` to convert OBJ |
| Where does HTTP go? | `src/sys/http.bas` (queue/pump) → `src/sys/telemetry.bas` (events) + `src/sys/lbrd.bas` (leaderboard) |
| Where does the sequence table come from? | `assets/sequence.txt` (data file, not code) |
| What is the `--scene` name for a stage? | `playingN` (combat), `bossN` (boss), `crawlN` (crawl) where N is the level number |
